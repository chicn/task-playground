# ai-task-run

`AI` にチェックが付いたタスクを AI が実行し、結果を Chihiro に渡す。

## 固定情報

| 項目 | 値 |
|---|---|
| Tasks | `collection://fa540ced-eb27-82c7-949c-876f41424223` |
| Slack の宛先（自分宛 DM） | ユーザー ID `U040VD7GF5J` |
| 成果物の保存先 | `~/.local/share/task-playground/outputs/YYYY-MM-DD/` |

## 対象の決め方

- `todo-capture` から呼ばれたとき: 今登録したタスク
- 引数なし: `AI` がチェック済みで、`AI state` が `待機` のタスクを `notion-query-data-sources` で拾う。`Status` が Done / Archived のものは除く

対象が0件なら、その旨を報告して終わる。

## 手順

### 1. 実行前の整理

1. 対象のタスクを一覧にして、ユーザーに見せる（実行は止めない）
2. 各タスクの `AI state` を `実行中` にする

### 2. タスクごとにサブエージェントで実行する

Agent ツールで、タスクごとに1つずつバックグラウンドで実行する。同時に動かすのは3件まで。サブエージェントには次を渡す。

- タスク名と、Notion ページの本文（背景）。本文に `Done:` と `成果物:` があれば、それを完了条件と成果物の形式として扱う
- `Source URL` の議事録ページがあればその URL
- 成果物のファイルパス: `~/.local/share/task-playground/outputs/YYYY-MM-DD/<タスク名>.md`（ファイル名に使えない文字は `-` にする。ディレクトリが無ければ作る）
- 下の「してよいこと」「しないこと」
- 成果物の構成: 冒頭に結論、続いて根拠と出典、最後に「Chihiro さんが次にやること」

#### してよいこと

- Web 調査
- Notion、Drive、ローカルファイルの読み取り
- 文章・資料・文面の下書きの作成（成果物のファイルに書く）

#### しないこと

- メールの送信、Slack への投稿（手順5の自分宛 DM を除く）、カレンダーの変更
- コードの push、ファイルや Notion ページの削除
- Notion の既存タスクの内容の書き換え（手順4の更新を除く）
- 推測で埋めること。出典が無い数字や事実は、成果物に書かない

`[連絡]` のタスクは、送らずに文面の下書きを成果物にする。

#### 要対応にするとき

次のどれかに当たる場合、サブエージェントは作業を止め、理由と質問を返す。

- 情報が足りない、またはタスクの意味が曖昧
- 判断（方針、金額、対人関係）が要る
- 調べても根拠が見つからない

### 3. 成果物を共有する

サブエージェントが成果物を書き終えたら、次を行う。

1. 成果物に秘密情報（パスワード、トークン、他社の機密、個人情報）が含まれていないか読んで確認する。含まれていそうなら、アップロードせずに `要対応` にし、理由を書く
2. `sharedoc upload <成果物のパス> --title "<タスク名>" --description "<一言の結論>"` を実行する。実行時に許可を求められたら、ユーザーの許可を待つ
3. 出力された URL を取る。URL が取れなかった場合は再実行せず、`要対応` にして、ShareDoc の一覧をブラウザで確認するよう伝える

ShareDoc の共有範囲は同じ組織の全メンバーになる。本人だけには限定できない。

### 4. Notion を更新する

成功したタスク:

- `Result URL` に ShareDoc の URL
- `AI state` を `レビュー待ち`
- ページ本文の先頭に3行以内の要約を追記する（`notion-update-page` の `insert_content`、position は start）

`要対応` のタスク:

- `AI state` を `要対応`
- ページ本文の先頭に、止まった理由と質問を追記する

`Status` は変えない。Done にするのは Chihiro。

### 5. Slack の自分宛 DM で知らせる

`slack_send_message` で、`channel_id` に `U040VD7GF5J` を指定して送る。タスクごとに1通ではなく、まとめて1通にする。

成功したタスクは、タスク名、一言の結論、ShareDoc の URL を書く。`要対応` のタスクは、タスク名と質問、Notion ページの URL を書く。

URL の書き方: URL は必ず単独の行に置く。URL の直後に全角文字（「。」「、」「）」など）を続けない。続けると、リンクが壊れる。

### 6. セッションの最後に報告する

結果を一覧で出す。

| タスク名 | 結果 | ShareDoc | Notion |
|---|---|---|---|

`要対応` のものは、何を聞くべきかを一言添える。
