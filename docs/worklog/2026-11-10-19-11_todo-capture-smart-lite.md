# todo-capture に SMART-lite のチケット書式を統合

## 目的
Tasks に登録されるタスクを、一覧で読める短い名前と、完了条件が分かる本文を持つチケットにするため。あわせて、議事録と Journal 以外（貼り付けたメモ）からも同じルールで登録できるようにする。

## やったこと
- 最初は `skills/ticketize/SKILL.md` を別スキルとして作った（19:11）。その後、リモートの main に todo-capture が入った（PR #1）ことが分かり、役割が重なるため todo-capture に統合して ticketize は削除した。ticketize のコミットは push 前だったので取り消し、履歴には残していない
- `skills/todo-capture/SKILL.md` に次を足した
  - タスク名: `[作業]` `[調査]` `[連絡]` `[検討]` の4分類、分類を含めて最大35文字
  - 本文のブロック: `Done:`（全チケット）、`参照:`、`成果物:`（AI に任せるチケットだけ）、`原文:`
  - 確認表に Done の列を追加
  - 入力にメモ（貼り付けたテキスト、箇条書き、ローカルファイル）を追加
  - 重複の確認で、タスク名に加えて本文の `原文:` も見る
- `skills/ai-task-run/SKILL.md`: サブエージェントに渡す本文の `Done:` と `成果物:` を、完了条件と成果物の形式として扱うと明記した
- `CLAUDE.md` と `README.md` の todo-capture の説明を更新した
- `~/.claude/commands/gijiroku.md`: Next Action の分類を2種類（調査・連絡）から4種類に増やし、期限の添え方を足した。チケット化の手順は入れていない（引き継ぎは meeting-notes の `CLAUDE.md` が持っている）
- meeting-notes と Succsess-Habits のリンクを、ワークツリーから main のチェックアウトに向け直した（`scripts/install.sh`）

## 判断
- 別スキルにせず todo-capture に統合する: ユーザーの決定。todo-capture はすでに2プロジェクトに入っていて、Journal 入力と ai-task-run への接続を持つため
- タスク名は分類込み35文字まで、分類は4種類: ユーザーの決定。Project 内の Todo 一覧で煩雑にならないことを優先した
- 元の文言の扱い: タスク名だけ短縮と分類付けを許し、原文は本文にそのまま残す。ユーザーの決定。これまでの「書かれた文言は変えない」を、タスク名に限って緩めた
- Project は新規に作らない。結ぶ先が分からないときはユーザーに聞く: ユーザーの決定
- `Done:` は AI が案を書き、確認表でユーザーが直す。推測になるものは `?` を付ける: Claude の判断。ユーザーの「全部を自分で書くのは面倒だが、書いた上で確認はしたい」という要望に合わせた
- メモ由来のタスクは `Source` を空にする: Claude の判断。`Source` の選択肢は Meeting と Journal だけで、選択肢を増やすかはユーザーに確認していない
- `~/.claude/commands/gijiroku.md` の変更: `CLAUDE.md` の「グローバルのファイルは書き換えない」と食い違うが、この会話でのユーザーの指示（分類を4種類にする）を優先した。規則のほうは変えていない

> ここに記載した判断はその時点の状況に基づくものであり、恒久的な決定ではありません。
