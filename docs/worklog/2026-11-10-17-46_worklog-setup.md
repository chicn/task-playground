# ワークログの仕組みの導入

## 目的
このリポジトリでやったことを `docs/worklog/` に残すため。ユーザー（Chihiro）から「worklog を導入したい」と依頼があり、`worklog-init` スキルの素材をそのまま使って導入した。

## やったこと
- `docs/worklog/` を作った
- `CLAUDE.md` の末尾に Worklog 節を足した（`worklog-init` の `assets/claude-md-section.md` を、書き換えずにそのまま使った）
- `.claude/hooks/worklog-check.py` を置いた（`assets/worklog-check.py` のコピー）
- `.claude/settings.json` を新規に作り、`PreToolUse`（Bash）と `Stop` の hook を設定した（`assets/settings-hooks.json` のコピー）
- 導入前の状態を確かめた。既存の作業記録のフォルダ、`CLAUDE.md` の Worklog 節、`.claude/`、`.gitignore` はいずれも無く、`python3`（3.12.3）は使えた
- hook の動作を確かめた
  - `git commit` を含むコマンドを渡すと、今日の日付のワークログが無い状態では `permissionDecision: deny` の JSON が出た
  - `git commit` を含まないコマンドでは何も出なかった
  - `.claude/settings.json` は `python3 -m json.tool` で正しい JSON と確認できた
- このファイルを書いた後に、同じ `git commit` の確認をもう一度行い、何も出ない（コミットを止めない）ことを確かめた

## 判断
- 導入先は、現在のセッションが入っているワークツリー（ブランチ `worktree-todo-skills`）にした。理由は、このセッションがワークツリーに隔離されており、main のチェックアウトには書き込まないため。判断したのは Claude。
- 素材の文面と設定は書き換えなかった。理由は、`worklog-init` が複数のリポジトリで同じ規則にそろえるために、素材のまま使うよう定めているため。判断したのは `worklog-init` の定めに従った Claude。
- コミットはしていない。理由は、`worklog-init` が「コミットは頼まれたときだけ」と定めているため。判断したのは `worklog-init` の定めに従った Claude。
- `.claude/settings.local.json` には入れず、`.claude/settings.json` に入れた。理由は、`settings.local.json` がコミットされず、ワークツリーや他のメンバーに届かないため。判断したのは `worklog-init` の定めに従った Claude。
- hook の確認用の入力は、ファイルに書いて渡した。理由は、コマンド行に `git commit` を書くと、ワークツリー隔離の検査が「git の形が複雑」として実行を拒否したため。判断したのは Claude。

> ここに記載した判断はその時点の状況に基づくものであり、恒久的な決定ではありません。
